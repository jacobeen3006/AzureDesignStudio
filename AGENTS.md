## OVERVIEW

Azure Design Studio — Blazor app for visual Azure architecture design. The primary target is the standalone MAUI Blazor Hybrid desktop app (Windows, and macOS via Mac Catalyst shipped as a .dmg): it runs every service in-process and needs no server. The WASM client + gRPC server keep building and tested but get no new work. Diagramming, validation, ARM/Bicep IaC generation, What-If, deploy, export. .NET 10, 13 projects in src/. Microsoft Global Hackathon 2022 winner.

## CONVENTIONS

- **SDK projects**: `Microsoft.NET.Sdk.BlazorWebAssembly` (WASM), `Microsoft.NET.Sdk.Web` (Server), `Microsoft.NET.Sdk.Razor` (Core), `Microsoft.NET.Sdk` (others)
- **Nullable**: enabled in all projects except AzureResources
- **ImplicitUsings**: enabled in all SDK-style projects
- **TFM**: `net10.0` (Desktop: `net10.0-windows10.0.19041.0` on Windows, `net10.0-maccatalyst` on macOS - chosen by host OS, one each); SourceGeneration targets `netstandard2.0`
- **Build authority**: `Directory.Build.props` owns repo-wide properties (MauiVersion pin, lock files, warnings, audit level); `Directory.Packages.props` owns every package version; each csproj declares only `Include=` on references; locked restore is a CI flag, not a repo property
- **gRPC**: protobuf in SharedModels, clients via `Grpc.Net.ClientFactory`, server via `Grpc.AspNetCore`
- **Auth**: Entra ID work+personal - MSAL redirect in WASM, native MSAL in Desktop (Windows: WAM broker; macOS: system browser on the `http://localhost` loopback, cache in the Keychain; device-code fallback on both), JWT + Microsoft.Identity.Web in Server; shared drawers use the `AdsHostAuth` host-override seam. Desktop identity (`DesktopIdentity`) = the MSAL account, else the Azure CLI token's claims (sign-out turns that fallback off)
- **Caller identity**: services read the caller from `context.UserState[ServiceTools.UserStateKey]`; Server's `CallerInterceptor` and Desktop's `InProcessCallInvoker` put it there
- **Azure credentials (deploy/what-if)**: a linked service principal for that subscription wins (secret in Key Vault on Server, `SecretStore` on Desktop = Windows Credential Manager / macOS login Keychain); otherwise the host's `IAmbientAzureCredential` (Desktop: the signed-in user). A broken link answers 404 - it never silently falls back to the user
- **Diagrams**: `Z.Blazor.Diagrams` 3.0.4.1 NuGet; fork-only APIs reimplemented in `AdsDiagram`/`AzurePort`/`VirtualNetworkPort`
- **Source gen**: Roslyn incremental generator with Scriban templates
- **ARM models**: `ResourceBase` → `ARMResourceBase` hierarchy, JSON serialization, `[GeneratedCode("ArmTypeGenerator")]`
- **DI registration pattern**: `AdsBicepDecompiler` uses custom extension method pattern (`AddAdsBicepDecompiler()`)
- **Testing**: xUnit — each test project independent. `Core.Tests` covers Core/Discovery/Workspace; `Server.Tests` calls the gRPC service classes directly with a fake `ServerCallContext` (the caller is `UserState[ServiceTools.UserStateKey]`) and never reaches Azure, and covers the in-process host (`InProcessTests`); it also holds the tests of the client's gRPC wrappers (`DesignGrpcService`, `DeployGrpcService`), reached through the Server's reference to the client

The plan hash binds the body plus the stack name
- Stack deployments are gated on the deployment-stacks what-if, not the plain one: the `StackWhatIf` RPC (`Discovery/Iac/StackWhatIf.cs` + `StackWhatIfClient`: PUT a temporary `deploymentStacksWhatIfResults/ads-<16 hex of the plan hash>`, read it, DELETE it; needs `deploymentStacksWhatIfResults/write`) issues a *stack* token (`WhatIfTokenGate.IssueForStack`) bound to `DeploymentStackBody.PlanHash` (template, parameters, policy, bypass flag, stack name), and `CreateStack` consumes it with `ValidateAndConsumeForStack`. A stack token and a deployment token refuse each other (`WHAT_IF_PAYLOAD_CHANGED`); changing the deny mode or bypass flag after the preview needs a new preview. `CreateStack` and `StackWhatIf` share `PrepareStackAsync` (validation, plan identity, stack body, guardrail policy, then the one resource-group lookup - so a refused request touches nothing in Azure). `StackWhatIf` also registers the scope+template+parameters plan hash so `ApprovePlan` finds a live preview. Rows are fail-closed (`StackWhatIfSummary.IndeterminacyReason`: unsupported rows, any `changeCertainty` other than `definite`, a delete/detach without an id): no token is issued for an indeterminate or guardrail-blocked stack preview, the reason comes back instead. Stack what-if rows carry no tags, so while the guardrail policy has tag rules every modify/detach/delete row is held back
- Deployment preflights (Waves B2/B4): `DeployService.WhatIf` runs `PolicyPreflight` and `QuotaPreflight` (`Discovery/Preflight/`, shared `PreflightSupport`) together (`Task.WhenAll`) as the last step of a what-if that succeeded, on the `after` payloads ARM already resolved, each on its own `ArmTransport` over the request's "arm" HttpClient and within `PreflightBudget` (30 s, internal). They are advisory: the token, plan hash, guardrail verdict and status code never depend on them (they run whenever `WhatIf` reaches its 200 answer: a guardrail-blocked review is still checked, even when its what-if is indeterminate, because only `WhatIfTokenGate.Issue` rejects indeterminacy and a blocked review never calls it; a what-if call that fails, an unblocked indeterminate review (400 from `Issue`) or an unreadable guardrail policy runs neither). They never throw except the caller's cancellation: no permission, throttling, a network failure, malformed JSON and the budget each become one note beside the findings already gathered, never an empty "no findings". Results ride on `WhatIfResponse.policy_flags`/`policy_notes` (13/14) and `quota_flags`/`quota_notes` (15/16): the engine's notes, then its `Caveats`. A management-group or tenant target gets one "not checked" note and no caveats; the stack what-if RPC runs no preflight (the drawer runs the plain what-if first in stack mode). `PermissionPreflight` has no probe for either
- Policy preflight: `POST {group or subscription}/providers/Microsoft.PolicyInsights/checkPolicyRestrictions?api-version=2024-10-01` (the subscription form for a resource group itself and subscription-level resources), Create/Modify rows only, at most 50 (`MaxResources`) and 3 at a time, `includeAuditEffect: true`, no `pendingFields`; a child resource sends its parent as `scope`. Verdicts (Deny/Audit/Other) come only from `contentEvaluationResult.policyEvaluations`, classified by `effectDetails.policyEffect`; `fieldRestrictions` describe pending fields and never become findings. The caveats say ARM enforces policy at deployment and that management-group-inherited assignments may not be reported
- Secrets never reach Azure Policy (`PolicyPreflight.Scrub`, applied to every `resourceContent`): (1) every string leaf containing a secure value is removed - a `secureString` parameter's value or any string inside a `secureObject` parameter (request parameters, else the template `defaultValue`); (2) `protectedSettings`, `customData`, `sharedKey`, `secureValue`, `connectionString(s)` and `adminPassword` go whatever they hold, as does the `value` of every `{ name, value }` array item (`appSettings`, `environmentVariables`, `env`) and of every `{ type: SecureString|SecureObject }` object; (3) string leaves under a key containing password, secret, connectionstring, accountkey, accesskey, token or sas go - booleans and numbers stay (`disablePasswordAuthentication` survives); (4) string leaves containing `AccountKey=`, `SharedAccessKey=`, `SharedAccessSignature=`, `sig=` or `-----BEGIN` go. Key Vault secrets and keys, `Microsoft.Web/sites[/slots]/config` and APIM named values are not sent at all (a note). Deployment parameters are never sent, and when the template or parameters JSON cannot be read nothing is sent
- Quota preflight: for each location with demand it reads Resource SKUs (`Microsoft.Compute/skus?api-version=2021-07-01&$filter=location eq '{loc}'`), compute usages (`Microsoft.Compute/locations/{loc}/usages`, 2026-04-01) and network usages (`Microsoft.Network/locations/{loc}/usages`, 2026-01-01). It counts the vCPUs of VMs, scale sets, AKS cluster pools and `agentPools` children (`maxCount` when autoscaling; a child takes its cluster's location) per SKU family and the regional `cores` total, plus public IPs (`StandardSkuPublicIpAddresses`/`PublicIPAddresses`); a Modify counts only the increase (after minus before), and a pool's before side is its `count` - the nodes that exist - never its `maxCount` (usage counts only running nodes; no before `count` releases nothing), so a redeploy over an autoscaled pool frees no quota that other demand in the region could hide behind. Status is Ok, NearLimit (`NearLimitRatio` 0.9), Exceeds, SkuUnavailable (size not listed in the location, or a Location restriction) or Unknown: an unknown size, count, family or vCPU count, or a read that failed, makes the checks it affects Unknown, never Ok. Spot/low-priority (a separate pool), App Service plans, Container Apps and Container Instances are notes, not checks; zone restrictions are a note. Demand is summed per location and size, so a release in the batch (a scale-in, a smaller size) offsets another resource's growth; ARM deploys independent resources in parallel, and a caveat says a new one may be checked before those vCPUs are freed. Quota is not capacity, and the caveats say so
- Exported templates are checked against Azure itself, not only offline: `ADS_WRITE_TEMPLATES=<dir> dotnet test src/AzureDesignStudio.Core.Tests --filter GalleryDesignTests.WriteExportedTemplatesWhenAsked` writes one template per palette entry plus the gallery designs and their stack bodies, for `az deployment group validate`/`what-if` (create nothing). `GalleryDesignTests.EveryPaletteEntryHasACompleteMinimalDesign` is the offline half
- Virtual machines and scale sets need a subnet (a VM may also sit in an availability set that is in one) and export their NIC alongside; the admin password is never stored - the template asks for the secure parameter `adminPassword`. Private endpoints and internal load balancers also need a subnet; a private endpoint takes its target from a link (or a typed id)
- Subnets export `defaultOutboundAccess` explicitly (`SubnetModel.PrivateSubnet`; omitted for delegated and reserved-name subnets; network api-version 2024-05-01 for vnets and subnets). A NAT gateway serves a subnet when it is linked to a node placed in that subnet, and needs a linked public IP. `DesignValidator` rules `outbound-access` (a machine subnet with no outbound path) and `retired-sku` (Basic and v1 network SKUs). Scans capture the top-level `sku` into `InventoryItem.Raw`, and `ScanDiffer` ignores a SKU that only the newer scan carries (no false drift on the first rescan)
- Scan status `Partial` = some query group failed or a listing was truncated. Partial scans are browsable but never the comparison baseline (`GetLatestCompletedAsync` and the Desktop rescan diff take `Completed` only) - a partial baseline makes what it missed look deleted
- Governance findings (Wave B3, `Discovery/Governance/`): a tenant scan can also collect sources, `ScanRequest.Sources` (null/empty = none; the Desktop scan tab's checkbox, on by default): `advisor` (`advisorresources` recommendations that are open - not Dismissed/Postponed/Completed, not suppressed, not Defender-sourced), `policy` (`policyresources` policy states, NonCompliant only) and `defender` (`securityresources` assessments, Unhealthy only, plus the `microsoft.security/pricings` plan tiers, which go into the manifest only). Each source runs one worker per subscription group beside the inventory, checkpointed as `"{source}:{groupKey}"`: Advisor and Policy run one Resource Graph query each, the Defender worker runs two, assessments then pricings, and its group counts as complete only when both finish untruncated (a truncated plans listing alone makes Defender unavailable). A source group that fails or is truncated is recorded in `ScanCheckpoint.FailedSourceGroups` only: that source becomes unavailable, the scan never becomes Partial, and its status, resource count, content hash and `FailedQueries` describe the inventory alone. The content hash is built at the end of a run from `ScanCheckpoint.GroupHashes` (one hash per stored inventory group, kept in the checkpoint), so a resume with only source groups pending still hashes the whole stored inventory; a group stored by a checkpoint that predates `GroupHashes` makes it null, never a hash that leaves rows out. A resume collects the sources the scan started with, skips completed source groups, retries failed ones and drops their failure once they succeed; `RequestKeyOf` is unchanged. Findings go to the workspace table `GovernanceFindings` (PK scan id + source + record id, no foreign key, guarded `CREATE TABLE IF NOT EXISTS`; Source stored as the enum name, while the manifest and checkpoint use the lowercase `GovernanceSources` key). Attack paths are out of scope: they need Defender CSPM plus agentless scanning, and their entities are not ARM ids
- `Discovery/Scan/ScanManifest` is the one manifest shape - the scan drawer, the Markdown report, report.html/report.json and MCP all read it. The four original members (`groupsCompleted`, `groupsFailed`, `rows`, `truncated`) keep their names and meaning; `sources` holds per source `collected`/`incomplete`/`unavailable`/`not-requested` with rows and a detail, and `defenderPlans` is null unless Defender was requested.

## [Unreleased]

### Added
- **Change feed spine (v2 plan 9.1):** `ChangeFeedCollector` queries the Azure Resource Graph `resourcechanges` table for a time window — newest-first, with Change Actor attribution (who changed it, which client, which RBAC operation); the existing Reader role covers it, no new permission. Rows persist idempotently into the workspace SQLite (`ChangeFeed` table, deduped by resource + change key) and the desktop `ChangeFeedService` exposes collect / feed / "what moved since the scan" reads, offline-capable.
- **Drift engine (v2 plan 9.2):** `ScanDiffer` compares two typeless inventories leaf-by-leaf (`properties.…` paths, array indices), classifying Added/Removed/Changed with old/new values — the same engine answers scan↔scan, design↔design and design↔live (`DesignTemplateReader` makes an ARM template comparable to a scan); platform churn like `provisioningState` is reported but never counted as drift. `LiveDrift` overlays the change feed on a scan to flag what moved since (New/Deleted/Modified + who). Desktop seam: `ChangeFeedService.DiffScansAsync` / `DriftSinceScanAsync`.
- **What-If review gate (v2 plan [65] impact preview):** server-side `WhatIfClient` / `WhatIfParser` / `WhatIfTokenGate` make ARM what-if a mandatory fresh preflight for deployment — every deploy must first preview the exact (subscription, resource group, template, parameters) payload and present the returned single-use token (15-minute TTL, bound to a payload hash); `CreateDeployment` refuses missing, expired, reissued or post-review-edited payloads. The gate fails closed: predictions containing Delete never deploy in this phase, and indeterminate reports (non-`Succeeded` status, Bad/unclassified rows) can never earn a token. The export drawer shows a review modal — counts, per-resource change rows, ARM's own caveats, approver identity — before Deploy.
- **Approved-plan-hash audit (v2 plan [62]/11.3):** `ApprovePlan` records a named approval for a plan's SHA-256 hash (EF `AdsPlanApprovals` table: principal, timestamp, plan hash); a plan is approvable only while its what-if preview is live. Applying is an append-only `AdsPlanApplyEvents` stream: a `Started` event carrying the canonical plan body and the SHA-256 of the consumed what-if token lands *before* the ARM mutation (consuming the approval in the same transaction). Terminals split by honesty: the *verified* ones are ARM's own truth - `Completed` on provisioningState=Succeeded, `Failed` only where ARM's 4xx proves refusal or provisioning finished failed/partial - persisted *before* any client notification; ambiguous submissions and unconfirmable ARM state land in `OutcomeUnknown`, the terminal-without-truth, which the deploy UI surfaces as an explicit "verify in Azure" step rather than a false failure. A lost client mid-deployment records the non-terminal `TransportLost` marker while ARM polling continues for the real result. Residual crash window, stated honestly: a server that dies before appending its terminal leaves a lone `Started` row - its truth lives only in ARM. The applied artifact outlives the consumed approval. The event vocabulary and rejection-proof predicate live in Core (`PlanApplyEventModel`) with offline column-contract tests - the first caught a `MinimumLength` that had silently rejected every 6-character `Failed` event. LRO completion is judged by `provisioningState`, so a deployment that finished failed no longer reports "completed".
- **Deployment-stack engine (v2 plan 12.3/[60][61], offline core):** `DeploymentStack` builds the ARM `Microsoft.Resources/deploymentStacks` PUT body — inline template plus the `actionOnUnmanage`/`denySettings` policy — in canonical form with the same `sha256:` identity hash the approval gate binds to, so an approved stack plan cannot be edited on the way to Azure. Validation fails closed (name/location/template/parameters/deny-locks diagnostics), and every `Delete` unmanage action is refused outright (`StackDeleteActionLocked`) — a stack must not become a side door for deletion before the Phase 13 decommissioning gates ship. `ReadManagedResources` reads a stack GET honestly (no silent drops; every unusable entry is a counted diagnostic) and `CheckDrift` answers the stack-out-of-sync guard: managed ids vs live inventory, compared case-insensitively like ARM, deterministic Synced/Untracked/Missing rows behind an `IsOutOfSync` flag. Execution (Server ARM client + proto) and the review-screen bypass follow; nothing here mutates Azure.
- **Stack execution (v2 plan 12.3):** `Deploy.CreateStack` deploys the reviewed design as a deployment-stack through the *same* double gate as `CreateDeployment` — fresh single-use what-if token plus a named approval bound to the canonical scope+template+parameters hash; the stack name and unmanage policy ride beside the hash (revert-plan convention) and land in the append-only apply trail keyed by stack name. Wire-form policy parses fail-closed: `missing_action` required, `Detach`/`Ignore` only, numeric or unknown values answered 400, `Delete` still `StackDeleteActionLocked`; the engine validates the body before the token burns. `DeploymentStackClient` sends the engine's exact bytes to the ARM stack endpoint over `ArmTransport.PutAsyncPolled` (resource-LRO: `Azure-AsyncOperation` preferred, `Location` fallback, headerless 202 re-polls the last status URI, writes never retried) and exactly one terminal apply event follows from ARM's own state — `Succeeded`=Completed, `Failed`/`Canceled` in a 200 = Failed, unreadable state / 5xx / transport deadline / client disconnect = `OutcomeUnknown`, never a failure claim and never silence.
- **Deploy-as-stack in the review drawer (v2 plan 12.3):** the What-If review modal gained an optional *deployment stack* mode — a switch plus stack name that reroutes the *same* approval to `CreateStack` instead of `CreateDeployment`, with the unmanage default surfaced honestly ("resources the stack later stops managing are detached, never deleted"). The plan hash, named approval and audit trail are identical to a plain deploy; the apply result maps to exactly three states — confirmed success, ARM-confirmed refusal with its reason, or outcome-unknown ("verify the stack in Azure before retrying"), never a silent failure claim.
- **Live-plane badge (v2 plan 12.1/[58] surfacing):** nodes and groups that carry a durable ARM resource id — the identity adoption stamps and live-plane refresh matches on — render a link badge on the canvas, so "this tile mirrors a real Azure resource" is visible at a glance and intent-only tiles stay clean. Desktop E2E proves both directions: an adopted design badges every node and group, a freshly dragged stencil badges none.
- **Guardrails on the deploy path (v2 plan 13.1/[36-final]):** the do-not-touch list is now server-side enforcement, not just a scan-time audit. Every what-if plan is judged against the policy on ARM-resolved resource ids and payload tags (pre-change state — moving a resource out of protection inside the same deploy does not escape it): a protected plan **earns no deploy token**, the review modal flags each protected row and renames the Approve button to "Blocked by guardrails". Because the token binds the preview's target set, `CreateDeployment` and `CreateStack` re-judge against the *live* policy before the single-use token is spent — tightening the list later stops already-reviewed plans too, and a veto never burns the token. The list is a single EF row (`AdsGuardrailPolicies`) written only through `SetGuardrailPolicy` with the authenticated principal recorded; malformed JSON is refused on write and an unreadable stored policy fails every deploy closed. A signed-in-only guardrails drawer (shield icon, top menu) edits scopes/tags/types policy JSON.
- **Decommission planner engine (v2 plan 13.2/[63][64][65]):** `DecommissionPlanner` (Discovery/Decommission) answers "what breaks if I delete these?" for a scanned inventory before anything is destroyed: dependency-safe **staged delete order** (Kahn batches over the config-derived reference graph — VMs before NICs and disks, disks only after their owning VM, peerings unordered), **refusal** for any resource a surviving resource still references (referrer named; edges onto cascade children collapse onto the selected parent), and evidence **blockers** from guardrails, `CanNotDelete` locks (exact or inherited scope), backup protection, plus a **delete-impact preview** — Key Vault soft-delete/purge facts, storage immutability, diagnostics/private-endpoint/peering breakage, orphaned survivors, RBAC loss — each row a stable machine code. Honesty rules: cycles refuse with the named cycle instead of a bogus order, unknown candidates refuse, missing evidence (locks/RBAC/backups/policy not supplied) is reported as caveats rather than a silent all-clear, and cascading children are listed as doomed but never staged (ARM removes them with the parent). Output is deterministic and casing-preserving. Offline core only: consumes no token, mutates nothing; the 13.4 two-stage destroy path must route through it. 26 new tests, suite 526/526.
- **Retain-before-retire, idle-cost ranking, protection windows (v2 plan 13.3/[66][67][68]):** three offline engines behind the planner. `RetainBeforeRetire` turns confirmed candidates into a per-resource retention manifest: backup coverage answered from scan evidence when present and reported as *unknown* when not (never a guessed `false`), an always-included config export (name/type/location/tags/live properties), data-loss kinds folded from the impact preview, and diagnostics sources listed for workspace candidates. `IdleCostRanker` answers "what is idle costing me?" — idle-capable disks/NICs/PIPs ranked by real Cost Management spend (provenance carried, totals from matched rows only) and the two reference signals the scan actually contains (leases/attachments, inbound references), idle reasons spelled per row; missing spend still ranks with `$0` left off and a caveat, and no usage telemetry is invented. `ProtectionWindowPlanner` manages the teardown-window locks: deterministic `ads-decom-<hash>` `CanNotDelete` protections applied only where unprotected (ancestor locks count), release removes the planner's own prefix only — an operator's foreign locks survive a release by construction, and a `windowId` narrows it to one window. 18 offline tests.
- **Decommission preview UI (v2 plan 13.2/[91] surfacing):** the desktop tenant-scan drawer gained a *Decommission* tab — pick any completed scan (a pure workspace-snapshot read; no Azure call leaves the tab), tick the rows to examine, and the planner answers on the spot: refusal banner, staged delete batches, blockers with kind and severity, impact preview, the implicit-cascade line, and a permanent "Not evaluated" caveat list — locks, RBAC and backups are never shown as an all-clear when no evidence was supplied. Manifest export [66]: confirmed candidates (refusals excluded) serialize through `RetainBeforeRetire` into a retention manifest written to the user's Downloads folder and opened with the default handler (`Launcher.OpenAsync` — MAUI 10 ships no save-file picker). The tab plans only; no delete verb exists yet, and the banner says so.
- **Runbook-as-code + two-stage destroy (v2 plan 13.4/[69][71]):** `DecommissionRunbook` (Discovery/Decommission) turns an allowed decommission plan into reviewable destruction: a Markdown runbook with the human checklist (peer review, owner notification from owner tags, CMDB record, monitoring teardown, Key Vault 90-day soft-delete dates, carried warnings/impacts/cascades) plus guarded az-CLI and PowerShell scripts. The flow is two-stage: stage 0 lands `ads-decom-` `CanNotDelete` window locks, stage 1 detaches from IaC control (empty-managed-set deployment-stack PUT body with `actionOnUnmanage=Detach` when a stack is named - resources keep running), and the purge stage is inert until the T+N undo window opens - both scripts carry an epoch guard, release only the window's own locks before deleting, then delete in the planner's staged order with existence verification. An abort stage releases the window and destroys nothing. The planner stays the refusal oracle (a plan with any refusal generates nothing), cascade children never get delete lines, and a `sha256:` plan hash binds candidates, order, detach body and window so the [62] approval names the exact reviewed bytes. Clock injected, output deterministic; nothing executes - 12 offline tests.
- **Runbook download in the Decommission tab (v2 plan 13.4/[69][71] surfacing):** an allowed teardown plan gains a *Save runbook* button — `runbook.md` + `purge.sh` + `purge.ps1` land in `Downloads\decom-<scan>-<window>\` and the toast names the shared `sha256:` plan hash and folder, so the review record binds to the exact bytes an approval must cite; the same plan shape re-runs into the same deterministic folder. A refused plan is a strict no-op: the button is disabled and the handler re-checks the plan, so refusal never leaks artifacts. Desktop E2E gate on a seeded scan: refusal → disabled button, nothing written; allowed → three artifacts on disk carrying the toasted hash, purge epoch-guarded to T+7d, dependency-ordered batches, abort path releasing only the window locks. Still fully offline — nothing executes.
- **Window execution — the app now lands the protection locks it staged (v2 plan 13.5/[70][72]):** the Decommission tab gained a *Window execution* section driving the first real ARM mutation in the decommission path — **locks only; the purge stage never executes from the app**. *Approve & land locks* demands the typed execution hash (a separate button and a separate `decom-execute` approval kind — plan approval and execution approval stay distinct records, the UI never auto-approves); execution reports per-scope `applied` / `alreadyLocked` (existing `ads-decom-*` lock vs foreign lock — abort only ever releases locks the app created) / `skippedGuardrail` / `failed`, plus the *nothing will be deleted* line and purge-until date; *Abort* releases the window's locks and never purges. Server-side the gate is hard before any ARM call: an exact-hash `decom-execute` approval (constant-time compare) or 412 `DECOM_APPROVAL_MISSING`, a server-recomputed execution hash or 409 (the wire `"O"` strings and unsorted scopes replayed through the same canonicalization), guardrails vetoed or unprovable scopes answered 403 `DECOM_GUARDRAIL_VETO` with zero writes, and `decom-purge` approvals refused outright so nothing in the app can ever authorize deletion; every attempt lands in the append-only `AdsDecomWindowEvents` stream keyed by `ApplyId`. `DecomExecution` (Discovery) owns the canonical execution hash — window + plan hash + subscription + purge instant + the exact sorted lock set, case- and order-insensitive — and the ARM lock name/identity parse; `ArmTransport` gained `DeleteAsync` (204-honest); the workspace stores approved execution hashes per scan+window so the button state survives restarts. A runbook→execution contract test replays the client signature through the server's wire-format parse and re-sort and proves it reproduces (drift there would make every real execute 409). 18 new offline tests, 579/579 green.
- **Local MCP server (v2 plan [93]):** new `AzureDesignStudio.Mcp` stdio server exposes the local workspace truth to MCP agents (Claude/Copilot CLI) as thirteen read-only tools — scan history, typeless inventory with type/scope/tag filters and paging, scan↔scan drift diff, change feed since a scan, the cost-meter cache, designs (list + `ads.json` document), exposure and unmanaged analysis, reachability queries over a target (v2 [16]: proven paths and caveats, never a closure claim), **plan-only** decommission plans and persisted window state. Pure engines live in `Discovery/Mcp/AdsToolEngine` (no DB/ARM access, clock injected); the host opens the SQLite workspace strictly read-only so the desktop app keeps writing, and a database from an older app version answers honestly empty for tables it predates. The decommission tool judges against the built-in default guardrail policy (none is persisted locally) and carries that caveat plus the standing `*-not-evaluated` lines; refusals report hashes only where computable. Nothing over MCP ever mutates the workspace or ARM — what-if and all mutating RPC deliberately stay server-side, so an agent cannot become a side door around the review UI. `dotnet run --project src/AzureDesignStudio.Mcp -- --db <workspace.db>`.
- **Side-by-side design comparison (v2 plan 9.2/[27]):** a *Compare saved designs* top-menu item (WASM + desktop) opens a full-height drawer rendering two saved designs as read-only mini canvases beside an authoritative change table: per-row kind chip (Added/Removed/Retyped/Changed/LinkAdded/LinkRemoved), expandable per-property old/new values and per-tile diff outlines (added green / removed red / changed amber) over `ZoomToFit`-framed panes. The answer comes from `DesignDiffEngine` — pure and deterministic: identity prefers the durable ARM id (survives adoption and live-plane refresh) over the saved entity id, links resolve endpoints through per-document id maps, malformed/duplicate/unidentified entries are counted diagnostics, and document order never changes the output. A side that cannot render its canvas degrades to the table alone; an unreachable server still answers from the desktop workspace's pending cache (banner shown) or reports the load failure honestly.
- **Phase 9 analysis surfaces reach the user (v2 plan 9.1–9.6 surfacing):** the desktop tenant-scan drawer answers the read-only governance questions directly. *Exposure*: findings over a chosen scan with severity counts, per-resource detail, remediation and the engine's coverage caveats — never an all-clear. *Changes*: collect the change feed (disabled with a reason when offline) and see drift since any scan — Modified/New/Deleted with caller attribution, `unknown actor` when the feed has none. *Cost*: live Cost Management spend per scan scope; the button names what it queries and every figure block carries provenance (source, scope, currency, window, as-of). *Inventory*: unmanaged/protected chips per row with an `N unmanaged` summary that doubles as a filter toggle, and a policy note that says `not loaded — protection not judged` rather than implying safety. *Report*: one click writes the governance bundle as Markdown to Downloads — scan id and as-of header, all sections, absent sections exported as absent, and the honest note that spend figures stay in the Cost tab because they need their own provenance. Desktop CDP gate on a seeded scan proves every surface (30 assertions, zero JS exceptions).
- **Phase 10 IaC surfaces reach the user (v2 plan 10.1/10.2/10.4 surfacing):** the offline engines get real UI in both hosts. *Import a text design (.ads.json)*: paste canonical `.ads.json`, typed validation answers inline (a bad version never half-loads), valid text lands entities and links on the canvas with names as labels. *Export* gains a *Text design (.ads.json)* radio — the code drawer previews the deterministic document the git-diff invariant promises. *Save Terraform (.tf)* on the Inventory tab turns any completed scan into an `azapi_resource` starting point in Downloads (per-type api-versions pinned, honest STARTING-POINT header, toast names the file). *Suggest globally unique resource names* drawer: per-row validity tags, deterministic workload+environment suggestions, *Apply* renames the node live on canvas and drawer. Live `checkNameAvailability` stays scheduled with the deploy-preflight phases. Desktop E2E gate: 33/33 checks, zero console exceptions.
- **Target-bound deploy execution and monitor (v2 plan 11.2):** the approved target is now a full ARM scope on the wire and on every mutating path. `DeployTarget` (resource group / subscription / management group / tenant) plus `management_group_id` and `location` join `DeploymentRequest` and `DeploymentOperationsRequest`; the resource-group default keeps every legacy client byte-compatible. `CreateDeployment` and the monitor resolve one `DeployTargetScope` before touching credentials — management-group and tenant submits authenticate through the linked subscription, ARM needs a deployment location outside a resource group and the contract requires it rather than guessing one. Staged batches submit at their own scope collection (`BatchScopePath`, RG pair keeps the historic endpoint); the what-if preview and the token/plan-hash identity bind to the same canonical scope path, so an approval can never ride across scopes. The monitor now lists every scope the target deploys under (`StagedDeploymentFamily.Collect` takes one listing per scope) and reads per-batch deployment operations at the target's own scope path — management-group and tenant deployments report honestly instead of listing empty. Each apply event records the exact scope it was bound to in `AdsPlanApplyEvents.TargetScope` (idempotent schema `ALTER` added; legacy rows stay null — their identity was the subscription+group pair).
- **Deploy target selector (v2 plan 11.2c surfacing):** the *Deployment Parameters* form now chooses the approved scope — *Resource group / Subscription / Management group / Tenant root* — showing only the identity fields the chosen kind requires (resource-group picker, management-group id, deployment location for anything outside a group). Client validation mirrors the server's target contract, so a half-named identity is a toast, never a round-trip. The what-if preview, plan hash, deploy, monitor and any targeted retry all read the same scope accessors, so the target the review modal names is provably the one submitted; deployment-stack mode stays resource-group-only (switch disabled with the reason), matching the `CreateStack` contract. The resource-group default keeps every legacy form byte-identical.

- **Reachability queries (v2 plan [16]):** `ReachabilityEngine.Analyze(target, snapshot)` answers "what can reach this resource?" from stored scan facts alone — walking the proven 8.1 edge derivation plus the Exposure engine's own findings backwards to the target. ### Fixed
- **Naming Apply left canvas labels stale:** renaming from the naming drawer mutated the model but only called `Diagram.Refresh()`, which does not re-render existing node components — the label kept the old name until an unrelated gesture. Now the per-model `Refresh()` the canvas itself uses after undo/delete, plus a drawer re-render so validity tags follow the new name; surfaced by the Phase 10 desktop gate.
- **Inventory browse picker phantom default:** the scan `<select>` visually pre-selected the newest scan while the component still held *no selection*, so *Save Terraform* and *Adopt* sat disabled until the user manually reselected the same entry. The tab now auto-loads the newest scan (the topology/exposure/cost convention) and the back-picker carries an explicit "select a scan…" placeholder — the DOM never claims a choice the app has not taken.
- **Decommission planner staged refused candidates:** `DecommissionPlanner` listed refused candidates in its staged-order rows, so a plan contradicted its own refusal — a refused resource never deletes while the refusal stands, yet the stage promised a safe order for it. Refused ids are now excluded from Kahn staging (regression test `RefusedCandidateIsNeverStaged_CleanSiblingsStillStage`); surfaced by the desktop smoke run.
- Desktop sign-in hang: the WAM broker requires `AcquireTokenInteractive` on the UI thread (MSAL `WamUiThread` contract); interactive acquisition now runs directly on the Blazor renderer thread instead of a timer-deferred sync block.
- **A broken Windows broker could kill the desktop app at startup:** WAM interop rethrows as an internal `MSALErrorException` that derives from no catchable public type, slipping past every `MsalException` filter — on a machine with a broken WAM the process died during startup account restore before the window settled. Every broker-adjacent path (account enumeration, silent acquisition, interactive sign-in, sign-out cache clear) now treats a broker failure as a cache miss: the app keeps running honestly anonymous (like WASM unauthenticated) and sign-in retries fall back to the device-code flow. Verified live on a broken-broker machine: app boots, the user drawer shows the sign-in prompt, and the full stencil/drop canvas works.
- Removed every UI-thread-reachable sync-over-async block in the scan stack (`ArmTransport` token fetch, `ResourceGraphClient` request build, `ScanControl.Pause` → `PauseAsync`) — each could freeze the desktop UI when the token cache was cold.
- Tenant-scan drawer history timestamps rendered a literal `dd.MM HH:mm` (Razor treated the format suffix as text); now proper `ToString` calls.
- Repeated "Tenant scan" menu clicks no longer stack duplicate drawers — the host seam closes the previous one first.
- Stencil drops landing on a node icon or group frame were silently swallowed: on `dragenter` into node/group content Chrome abandoned the external drag session (observed: `dragenter` on the icon IMG, then no further `dragover` dispatch and no `drop`), so grouping a stencil into an availability set (or dropping onto any node) did nothing. The `AdsDropZone` seam now `preventDefault`s `dragenter`, restoring drop delivery over node/group content (verified end-to-end on the desktop app: drop-groups, group-drag-carries-child, port links, undo/redo round-trip).
- Desktop "Adopt scan" froze at *Adopting…* — three stacked defects, each masked by the next: (1) in-memory graphs from `AdoptEngine`/`LivePlaneMerger` carry base `AzureNodeDto` members while the canvas loader resolves AutoMapper maps by runtime type, so the canvas load threw *Missing type map* and killed the Blazor circuit mid-handler; `GetNodesDto` re-types base DTOs to their registered derived DTOs (regression test `TypedGraphReloadTests`). (2) An unauthenticated server answered `401`/`Unauthenticated`, which bypassed the offline-save fallback and escaped the handler — saves now defer the design to the offline store for any save the server cannot take (transport down or not signed in) and sync after sign-in, and the adopt handler catches and reports failures instead of killing the circuit (a dead circuit is indistinguishable from a frozen drawer). (3) Kestrel refuses HTTP/2 on cleartext URL endpoints, so native gRPC against a dev server never completed; the server gained a loopback h2c listener (`http://localhost:5204`, HTTP/2-only) and the desktop `ServerUrl` default follows. Verified end-to-end on the desktop app via CDP: adopt → save deferred offline (workspace row pending, `SyncedAt` null) → canvas reload renders the adopted node → success message.

Surface the durability work in the Desktop app: startup through `WorkspaceStartup` with a visible corruption notice and a failure page, a workspace-data drawer for backup and restore, the scheduler, and a data-root override that makes the built app safely testable.

Purpose: success criteria 4 and 1 as a user experiences them - a corrupted workspace is surfaced (not silently replaced), a backup can be taken and restored from the UI, and an old workspace upgrades on launch. All mechanics were built and unit-tested in plans 04-02 to 04-10; this plan is host glue, so its verification is a compile on the Mac target, a compile of the shared client, and a scripted launch of the built app.

Output: the MauiProgram startup swap, host seam and menu item, drawer, native failure page, reveal helper, a verification script, and the scheduler start.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user -> file picker -> restore | The user chooses an arbitrary file that is staged and later becomes the workspace |
| app -> OS shell | The reveal action starts the platform file manager with a path argument |
| environment -> data root | `ADS_DATA_DIR` redirects where all databases and backups live |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-40 | Tampering | Restore candidate chosen from the picker | high | mitigate | The UI only calls `StageRestoreAsync`, which verifies the staged copy (plan 04-09); a rejected file shows every reason and nothing is staged; the swap happens at the next launch before connections open |
| T-04-41 | Elevation of Privilege / injection | Reveal action starting `explorer.exe` / `open` | medium | mitigate | `ProcessStartInfo.ArgumentList` with the path as a single argument, `UseShellExecute = false`, path must exist and sit under the data directory; no string-built command line |
| T-04-42 | Information Disclosure | deploy.db backups (contain client secrets) surfaced in the UI | high | mitigate | The drawer lists only `WorkspaceBackup.List(<backups root>)` of the workspace stem; `backups/deploy` is never read, offered or revealed by this code (grep acceptance + prohibition) |
| T-04-43 | Tampering | `ADS_DATA_DIR` pointing the app at an attacker-chosen folder | low | accept | Same trust level as the user's own environment and as the existing `ADS_WORKSPACE_DB` for MCP; used only for testing and documented; nothing is created outside the chosen directory |
| T-04-44 | Denial of service | Failed upgrade leaving the user with a crashed launch | medium | mitigate | `WorkspaceUpgradeException` and the deploy-database failure route to a native page naming the backup, the error and the data folder; the premigration backup already exists by then |
| T-04-SC | Tampering | NuGet installs | high | accept | No package is added; CommunityToolkit.Maui is explicitly not used (CONTEXT decision on the manual-backup surface) |
</threat_model>

<objective>
Bring the Desktop's `deploy.db` under the same schema authority: a provider-free `SqliteDesignDbContext` with a generated, guarded baseline in Services, a startup helper that backs up, adopts legacy columns and migrates, and a guard that no source outside the server bootstrapper calls the model-creation method any more.

Purpose: `deploy.db` is the fourth place the product creates a database by hand, and Phase 5 adds tenant columns to tables that live in it; without a migration history those columns would need a fifth ad-hoc DDL block. RESEARCH assumption A2 and CONTEXT ("include deploy.db in Phase 4 as a separable final wave") put it in scope; it is isolated in its own plan so it can be dropped without touching stored data.

Output: derived context, generated SQLite migration set, design-time factory, `DeployDbStartup`, the Desktop edit, tests, and the extended source guard.
</objective>

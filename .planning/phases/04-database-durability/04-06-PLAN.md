## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process -> SQL Server | Tests create, migrate, back up, restore and drop databases on whatever server `ADS_TEST_SQLSERVER` names |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-19 | Tampering / Information Disclosure | Tests pointed at a real server through the environment variable | high | mitigate | The tests only run when the variable is set explicitly; every test creates a uniquely named database and drops it; no production host, Key Vault or real connection string appears in the repository; the local script and the CI job use a container that exists only for the run |
| T-04-20 | Information Disclosure | SA password in `build.yml` and the script | low | accept | Ephemeral credential for a throwaway container with no data and no network exposure beyond the runner; stated in a comment; not reused anywhere |
| T-04-21 | Repudiation / data loss | Rollback procedure that was never exercised | high | mitigate | The BACKUP, RESTORE VERIFYONLY, Migrate, RESTORE WITH REPLACE sequence is executed by a test on every CI run and returns the database to its pre-upgrade rows with no history table |
| T-04-22 | Denial of service | Concurrent `Migrate()` from several replicas or processes | medium | mitigate | Three concurrent migrations are tested (EF takes a database-wide lock); production runs one replica and the runbook keeps it that way until a bundle flow exists |
| T-04-SC | Tampering | NuGet installs and the container image | medium | accept | No new package (the SQL client flows from the Server project reference); the image is Microsoft's official `mssql/server` tag, used only for tests |
</threat_model>

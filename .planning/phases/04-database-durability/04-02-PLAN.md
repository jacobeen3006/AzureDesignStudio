The recorded decision (CONTEXT) is baseline-as-guarded-SQL with the first migration being the history every installation carries.

Output: the generated baseline migration (Up replaced by guarded SQL), the design-time factory, `WorkspaceSchema` and `LegacyAdoption`, the slimmed `WorkspaceDb`, and tests proving L1/L2/L3 upgrades, fresh-versus-upgraded parity and the pending-model-changes guard. Later plans in this phase extend `WorkspaceSchema`: premigration backup (04-07), unique-index guard (04-10).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk workspace file -> upgrade code | A user's real database (possibly legacy, possibly partially upgraded) is altered in place |
| app process -> SQLite file | A second process (the MCP server, a second app instance) may hold or have abandoned a migration lock |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Tampering / data loss | Baseline migration and legacy adoption on a user's existing `workspace.db` | high | mitigate | Baseline is `IF NOT EXISTS` only (never drops, never recreates); legacy adoption only appends two nullable columns and only when no history exists; tests assert every table's row count is unchanged for L1, L2, L3 and a model-built file; the premigration backup is added in plan 04-07 before this pipeline can run against a real file |
| T-04-04 | Tampering | SQL text built in `LegacyAdoption` | low | mitigate | Table and column names are compile-time constants inside the method; existence checks use bound parameters; no caller-supplied identifier reaches SQL |
| T-04-05 | Denial of service | Abandoned `__EFMigrationsLock` row blocks `Migrate` forever (verified to hang in research) | medium | mitigate | `MigrateAsync` runs under a 30 s bound; the timeout raises `WorkspaceUpgradeException` naming the table, the recovery statement and the file; the lock row is never deleted automatically (plan 04-10 proves the recovery, plan 04-12 documents it) |
| T-04-SC | Tampering | NuGet installs | high | accept | No package is added in this plan; the Design package and tool were gated and locked in plan 04-01 |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server process -> SQL Server | Startup runs DDL against the production database with the application's login |
| operator configuration -> bootstrapper | `Database:*` keys and the connection string decide what the host does to a database |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Denial of service / Repudiation | `Migrate()` creating an empty database from a mistyped connection string | high | mitigate | `Database:AllowCreate` defaults to false; `Decide` refuses a missing database unless it is true; the live refusal is exercised against SQL Server in plan 04-06 |
| T-04-07 | Elevation of Privilege | Runtime application login performing DDL | medium | accept | Already required today (startup creates tables); a single replica runs the host; recorded in the runbook (plan 04-12) as accepted until a migration-bundle flow with a separate deployment identity exists; `Database:Migrate=false` is the switch for that flow |
| T-04-08 | Tampering / data loss | Baseline T-SQL against a populated legacy database | high | mitigate | Every CREATE is behind `IF OBJECT_ID ... IS NULL`, every column add behind `COL_LENGTH`; nothing drops or recreates; fresh-versus-legacy parity and row retention are proven on a real SQL Server in plan 04-06; rollback is restore of the pre-upgrade backup (rehearsed there) |
| T-04-09 | Tampering | Migration code executing from an unexpected call site | medium | mitigate | `MigrateIsCalledOnlyBySchemaOwners` limits the call sites; the MCP project is explicitly forbidden |
| T-04-SC | Tampering | NuGet installs | high | accept | No package is added in this plan; the Design package was gated in plan 04-01 |
</threat_model>

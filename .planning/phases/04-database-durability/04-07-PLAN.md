<objective>
Assemble the workspace startup state machine: staged integrity check, quarantine with a notice, and a premigration backup inside the upgrade pipeline so no existing database is ever migrated without a backup.

Purpose: success criterion 4 (startup `quick_check` surfaces a deliberately corrupted workspace instead of opening it) and the "back up before migrating, never re-create a user database" rule from the roadmap. CONTEXT records the user's choices: quarantine (never delete), a fresh workspace created automatically, and a notice naming the quarantine path and the backups.

Output: `WorkspaceStartup` (+ report types), the premigration backup in `WorkspaceSchema`, an internal `WorkspaceDb` constructor for an already-upgraded file, and tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| damaged or foreign file at the workspace path -> startup code | Whatever sits at `workspace.db` is opened, checked, moved or migrated |
| workspace directory -> other local users | Quarantine and backup files hold tenant inventory and designs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-23 | Denial of service / data loss | Silently continuing on, or silently replacing, a corrupt workspace | high | mitigate | Integrity check at every start; `Corrupt` is quarantined (moved, never deleted) with a notice naming the path and the backups; tests assert the moved bytes are identical to the damaged file |
| T-04-24 | Tampering / data loss | A healthy file moved aside because another process held it or permissions failed | high | mitigate | `Inconclusive` outcomes throw and move nothing; live-file checks open read-write so a leftover WAL recovers; classification pinned in plan 04-05 |
| T-04-25 | Tampering / data loss | Migration of an existing database with no recoverable copy | high | mitigate | Premigration backup is written and verified first; a backup failure aborts the upgrade with the live file unchanged (tested); the invariant is in `UpgradeAsync`, so the plain `WorkspaceDb` constructor has it too |
| T-04-26 | Information Disclosure | Quarantined file readable by other local users | medium | mitigate | User-only mode on Unix after the move (a move keeps the original permissions); profile ACL on Windows; location is the user's own data folder |
| T-04-SC | Tampering | NuGet installs | high | accept | No package is added in this plan |
</threat_model>

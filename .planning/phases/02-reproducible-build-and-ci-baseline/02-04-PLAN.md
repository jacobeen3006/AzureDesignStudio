<objective>
Close the vulnerability gate honestly: audit at High/Critical severity, promoted to errors by the warning policy that is already on, with exactly one advisory exception that carries a build-enforced expiry date and no per-project escape hatch.

Purpose: BUILD-04 and SC#3. The measured facts: the .NET 10 SDK already audits transitives by default at `low` (E24), `TreatWarningsAsErrors` promotes `NU1903` when `NoWarn` is cleared (E25), `NuGetAuditSuppress` silences the advisory end-to-end (E27), and the mechanism has no built-in expiry — hence the `Directory.Build.targets` target. Two pre-existing `<NoWarn>$(NoWarn);NU1903</NoWarn>` blocks (WASM line 21, Core line 12) make the gate bypassable and must be deleted in the same commit that adds the suppression (Pitfall 9). Deleting them exposes a second high advisory the suppression does not cover: `System.Security.Cryptography.Xml` 10.0.10, which the Bicep/Azure.Deployments graph pulls into WASM and Desktop. That is why plan 02-01 pins it to 10.0.13 first — a second suppression here would violate BUILD-04's one-entry rule, so the pin is the remediation and this plan only has to prove it. `NuGetAuditMode` is raised to `all` because the SDK defaults it to `direct` below .NET 10 and `SourceGeneration` targets `netstandard2.0`; measured, the only advisory left after the pin is AutoMapper's.

Output: `Directory.Build.props` with the audit level, the single suppression item and the expiry property; `Directory.Build.targets` with `AdsCheckAuditSuppressionExpiry`; both `NoWarn` blocks gone; four recorded probes proving the gate blocks, the allowlist covers, and the expiry fires.

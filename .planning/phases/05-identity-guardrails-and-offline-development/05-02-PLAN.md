<objective>
Put the typed caller in front of every Design and Deploy RPC, answer an identity failure as an in-band 401 everywhere, remove the old user-id derivation, and prove the two compatibility promises: a legacy URI-only token still reaches its rows, and a client never retries a 401.

Purpose: completes Success Criteria 1 and 2 (IDA-01, IDA-02) on the foundation of plan 05-01. The guardrail, settings, approval and decommission plans that follow all start from a typed `caller`.

Decisions implemented (CONTEXT.md; ids assigned by this phase's planning):
- D-08 (costly): the user id comes only from AdsIdentity (oid and tid, URI claim or short spelling, never sub); a failure is an in-band typed 401.
- D-12 (decided autonomously): the 401 reuses the services' existing in-band convention (status in the response message); no proto field is added, and the client must not treat it as a reason to queue or retry.
- D-14 (decided autonomously): the caller reaches the services through UserState and is read once per RPC.

Output: all 20 Design and Deploy RPCs resolve the caller first, the legacy accessor is deleted, and the table, legacy-claim and client-contract tests exist.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bearer token -> validated principal | JwtBearer and Microsoft.Identity.Web validate signature, issuer, audience and scope before any service code runs |
| principal -> every RPC body | Each RPC derives the caller once from the validated principal; nothing in a request message names a user or tenant |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-02 | Denial of service / integrity | A permanently bad token answered with RpcException(Unauthenticated) | medium | mitigate | Failure is an in-band 401 in the response; IdentityRpcTests prove no RpcException for all 20 RPCs and the client wrapper tests prove no offline queue entry |
| T-05-38 | Elevation of privilege | A surviving second derivation of the user id (the removed legacy accessor) that ignores tid | high | mitigate | The accessor is deleted; two grep gates keep its name and the string-to-Guid construction at zero; the completeness fact fails when an RPC is missing from the table |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package is added by this plan |
</threat_model>

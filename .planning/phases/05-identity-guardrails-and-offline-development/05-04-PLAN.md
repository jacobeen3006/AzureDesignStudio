<objective>
Give each tenant two audited settings an administrator controls - allow self-approval (default off) and guardrail policy mode (replace by default, merge as the alternative) - and make guardrail evaluation honor the mode.

Purpose: IDA-06 needs a persisted, audited self-approval setting before the approval rules in plan 05-07 can read it, and IDA-05's inheritance rule needs both mode semantics defined once.

Decisions implemented:
- D-02 (costly, settled): self-approval is refused as a separate rule; a Guardrail.Admin can switch on a per-tenant allow-self-approval setting (default off) and every change is audited.
- D-05 (costly, settled with an interpretation to confirm): per-tenant guardrail policy mode, replace (default) or merge, changed by Guardrail.Admin and audited. The user's wording ("Option 1 and option 2 are available to choose") was ambiguous; this plan records the reading visibly here, in the operator docs (plan 05-08) and in the phase report so it can be corrected cheaply: both modes are supported, selected per tenant.
- D-15 (decided autonomously): audit tenant setting changes in AdsSecurityEvents.
- D-18: tests run on AdsServerFactory and TenantIsolationTests.

Output: two new RPCs on the Deploy service, the settings logic, GuardrailPolicy.Merge, mode-aware policy loading, and tests.
</objective>

<objective>
Give every request one trustworthy, typed caller: user id, tenant, tenant scope key and roles, derived from the validated principal in one pure place, with identity failure answered in-band as a 401 by every Design and Deploy RPC.

Purpose: Success Criteria 1 and 2 (IDA-01, IDA-02), and the foundation every other plan of the phase stands on (roles, scopes, markers, test helpers).

Decisions implemented (CONTEXT.md; ids assigned by this phase's planning):
- D-04 (costly): the single-user Desktop host is declared by a UserState marker, never by claims; it implies Guardrail.Admin, Deploy.Approver and self-approval; a personal-account scope implies Deploy.Approver.
- D-08 (costly): AdsIdentity.TryFrom accepts the mapped oid and the legacy URI claim through Guid.TryParse, validates tid the same way, never uses sub, never flips MapInboundClaims, and answers with an in-band typed 401.
- D-11 (decided autonomously, supersedes the earlier Server/Auth placement): AdsIdentity lives in the Services project so DeployService and the Desktop in-process host can read it.
- D-12 (decided autonomously): the 401 reuses the services' existing in-band convention (status in the response message); no proto field is added.
- D-14 (decided autonomously): the tenant reaches the services through the same UserState caller mechanism.
- D-17 (decided autonomously): scope key is tid for organizational tokens and the user's oid for personal-account tokens.
- D-18 (decided autonomously): tests run on the Phase 3 AdsServerFactory with a test auth handler that can emit chosen claims.

Output: AdsIdentity and AdsCaller, ServiceTools.TryGetCaller, all 19 caller sites converted, the in-process marker, extended test helpers and the first identity test classes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bearer token -> validated principal | JwtBearer and Microsoft.Identity.Web validate signature, issuer, audience and scope before any service code runs |
| principal -> AdsIdentity | The services accept only claims of the validated principal; nothing in a request message names a user or tenant |
| host -> services (UserState) | The in-process Desktop invoker is the only code that may declare a single-user host |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

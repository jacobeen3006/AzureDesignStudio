Only the right role can read or change a tenant's guardrail policy, every change leaves a durable record in the same commit, and a what-if preview with its plan hash and token belongs to one scope and one requester.

Purpose: Success Criterion 4, first half (IDA-04) and the gate half of IDA-05. Today any authenticated user reads and overwrites the policy, the change leaves no record, and a preview from one tenant can be approved or consumed by another.

- D-18: tests run on AdsServerFactory and the extended test auth handler.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> guardrail RPCs | The request carries only the policy body; the right to administer comes from the validated principal and the host marker |
| in-memory preview gate -> approval | The gate decides which preview a caller may approve or consume |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-05-09 | Elevation of privilege | SetGuardrailPolicy open to any authenticated user (today) | high | mitigate | Role gate on both RPCs (Guardrail.Admin, personal account or single-user host); GuardrailAuthorizationTests pin the matrix over service and host |
| T-05-13 | Repudiation | A policy change with no record | medium | mitigate | GuardrailPolicyChanged event in the same commit as the row, naming the principal; one-commit interceptor test; the event never holds the policy body |
| T-05-25 | Elevation of privilege / information disclosure | A preview, plan hash or token from another scope approved or consumed | high | mitigate | Gate entries carry the scope; the scope-aware peek and consume return stale for any other scope without revealing existence |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package is added by this plan |
</threat_model>

<objective>
Prove, with one thin end-to-end path first, that the real server can be booted by a test and called over gRPC without Azure, then pin its authentication contract and service surface.

Purpose: success criterion 2 of the phase (a channel over TestServer reaches every service through a test authentication handler) and the reachability half of criterion 4 (`Program` reachable from the test project). Plan 03-03 then moves the database choice from the compiler to configuration and puts the data on a temporary SQLite file; this plan deliberately runs on the server's existing in-memory database (selected by `Database:Provider` in Release, by the compile-time default in Debug), so the harness itself is proven independently of that change and both build configurations take the same path today.

Output: a public entry point, a `WebApplicationFactory` fixture, a test authentication handler, a channel helper, and `ServerHostTests` covering boot, round trip, `Unauthenticated`, `PermissionDenied`, scope drift and the three-service surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process -> in-memory server host | Test code mints identities; the real authentication, authorization and interceptor pipeline must still decide access |
| gRPC client -> Design/Deploy/Cost services | Anonymous and under-scoped callers must be refused by the real pipeline, not by test doubles |
| server tests -> outside world | The harness must never reach a tenant, price API, Key Vault or a developer's data |

## STRIDE Threat Register

Plan 03-01 used T-03-01 and T-03-02; numbering continues here.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Spoofing / Elevation of Privilege | Header-driven test authentication scheme | high | mitigate | Handler, scheme name and headers exist only in `AzureDesignStudio.Server.Tests`; `Program.cs` gains only `public partial class Program`; acceptance greps over `src/AzureDesignStudio.Server` must find no handler or header (plan 03-06 turns this into a permanent test) |
| T-03-04 | Information Disclosure | Tests reaching a live tenant, the price API, Key Vault or a developer database | high | mitigate | Harness uses the in-memory database, sets no vault or credential, and calls only RPCs that answer before any outbound request (Design list, guardrail read, Cost with an invalid request); prohibitions forbid network-reaching calls |
| T-03-05 | Information Disclosure | Application Insights channel started from the checked-in sample connection string | medium | mitigate | `ApplicationInsights:ConnectionString` is set to an empty string through `UseSetting` in the factory |
| T-03-06 | Elevation of Privilege | `[Authorize]` and `[RequiredScope]` enforcement on Design and Deploy | high | mitigate | Real-pipeline tests assert `Unauthenticated` without credentials and `PermissionDenied` for an authenticated caller without the scope claim; a drift test ties the issued scope to `AzureAd:Scopes` |
| T-03-SC | Tampering | NuGet installs | high | mitigate | No package is added in this plan; the Mvc.Testing and Sqlite packages were gated and locked in plan 03-01 (Approved in RESEARCH.md Package Legitimacy Audit) |

# Azure Design Studio — 30 researched improvement proposals

Status: IN PROGRESS — proposal only; not an approved roadmap or implementation plan.
Baseline: `fa62bb9` (user-provided). Scope: new proposals only, after Phase 9 trust gate for new UI; excludes all current v1/v2 and GSD roadmap scope.

## Landscape and positioning

| Product/source | Verified from first-party documentation | Qualified weakness / opening for ADS |
|---|---|---|
| Eraser | Connects Azure at subscription or tenant scope with read-only data sources, scans to a model, and uses that model for AI-generated diagrams; its cloud diagram docs say the model reflects the latest scan, and users must manually rescan after changes. [S1][S2] | The docs establish read-only scan-to-diagram and a rescan workflow, not a design-to-deploy ARM/Bicep round-trip or Azure change-control execution. This is a documented-scope gap, not a claim that the product lacks every capability. |
| Hava | Vendor feature page describes read-only Azure connections, scheduled/on-demand sync, retained versions, arbitrary revision comparisons, resource-level cost estimates, and diagram/list/security views. [S3] | Hava explicitly says it imports config and lays out diagrams with “No More Drag & Drop”; it is an auto-documentation view, not an editable architecture design canvas. Vendor feature claims are not independently benchmarked. |
| Brainboard | Its current official docs describe visual cloud design, collaboration, generated Terraform/OpenTofu, and asynchronous cloud import that generates a design, code, and state. [S4] | The reviewed docs center Terraform/OpenTofu; no native ARM/Bicep editing/export flow was documented on the official overview page. Scope the gap to its published docs, not a categorical feature absence. |
| Azure Resource Manager provider metadata | Microsoft documents provider metadata as the source for provider registration state, valid resource types, supported locations, and API versions; it warns that provider registration grants an app in the tenant and should be limited to providers actually needed. [S5] | Native metadata is authoritative but spread across subscription/provider APIs; ADS can turn it into safe preflight and compatibility evidence without attempting auto-registration. |

The unoccupied opportunity is a tenant-local Azure workspace that does more than draw a scanned snapshot: it can explain catalog/runtime compatibility, preserve reproducible evidence, and make planned changes inspectable without weakening the existing approval boundary. Competitors establish useful scan, version, diff, and visual patterns; ADS's differentiated proposal is to connect those patterns to Azure-native ARM/Bicep and its local Discovery/Workspace engines. These are improvement proposals, not verified market exclusivity claims.

## Backlog

### Catalog, deployment preflight, and artifact integrity (1–8)

1. **[Fix][M][P0] Make scan hashes represent the scanned state.** `ScanEngine.RunAsync` hashes only ID/type/name/location, and on resume hashes only newly queried groups; tags and `Raw` properties are absent, so a changed config can retain the same checkpoint hash. Build the digest from all persisted normalized rows (including canonical tags/properties) after resume, with deterministic ordering. **Anchor:** `src/AzureDesignStudio.Discovery/Scan/ScanEngine.cs:92-120,148-164`; `InventoryItem.cs:66-75`. **Accept:** changing any property/tag changes the hash; resuming a partially completed scan produces the same hash as a clean scan of identical rows. **Depends:** none. **Source:** source audit; vendor data model permits provider-defined properties [S5].

2. **[Fix][M][P0] Persist terminal scan status after cancellation.** The cancellation handler sets `status = "Canceled"` but passes the already-cancelled token into `ScanFinishedAsync`; sink persistence can therefore be cancelled too, leaving a scan recorded as Running. Persist terminal state with a bounded independent token and retain cancellation as the primary outcome. **Anchor:** `ScanEngine.cs:138-150`; `WorkspaceScans.cs:83-95`. **Accept:** cancel during query and during page persistence both result in a durable Canceled/Interrupted record, never a resumable phantom Running record. **Depends:** none. **Source:** source audit.

3. **[Fix][M][P1] Make resumed snapshot writes idempotent and pick the newest row.** A resumed group can insert duplicate `(ScanId, ResourceId)` rows; `TenantScanSession.GetSnapshotsAsync` then uses `DistinctBy` on rows ordered by type/name, which does not implement its “last write wins” comment. Upsert by case-insensitive resource ID and/or sort by observation time before deduplication. **Anchor:** `WorkspaceScans.cs:59-80,117-125`; `TenantScanSession.cs:42-46`; `WorkspaceDbContext.cs:40-44`. **Accept:** replaying the same group leaves one row per resource and newer properties win; add a legacy-duplicate migration/cleanup test. **Depends:** Phase 4 migration authority. **Source:** source audit.

4. **[Fix][M][P0] Bind a resume checkpoint to its original scan request.** `TenantScanSession.StartScanAsync` accepts a new subscription list while loading the latest checkpoint, and `ScanEngine` skips completed groups by a hash derived from group contents; make resume validate scope and subscription-set identity before reusing that checkpoint. **Anchor:** `TenantScanSession.cs:49-70`; `ScanEngine.cs:86-93,153-160`; `WorkspaceScans.cs:17-23`. **Accept:** changing scope, subscription membership, or grouping parameters refuses resume with a clear explanation; exact same request resumes. **Depends:** none. **Source:** source audit.

5. **[Fix][S][P1] Report partial scans as partial, not successful.** Failed ARG query groups are recorded in `FailedQueries`, but the engine's terminal status starts as `Completed` and remains so after group failures. Distinguish Completed, Partial, Canceled, and Failed; ensure consumers never treat Partial as an all-clear baseline. **Anchor:** `ScanEngine.cs:126-149`; `WorkspaceScans.cs:83-96`; `TenantScanDrawerTemplate.razor` (scan history/status). **Accept:** injected single-group failure produces Partial, preserves successful rows, and drift/coverage views show incompleteness. **Depends:** none. **Source:** source audit; Eraser likewise documents its model as the last scan, reinforcing the need to show scan freshness/completeness [S2].

6. **[Fix][S][P1] Decode Key Vault plaintext with the same encoding used by encryption.** `CryptoService.Encrypt` encodes UTF-8 while `Decrypt` decodes `Encoding.Default`, so non-ASCII subscription values can be corrupted on hosts whose default encoding differs. Use UTF-8 explicitly and pin the serialization contract. **Anchor:** `src/AzureDesignStudio.Server/Services/CryptoService.cs:24-35`. **Accept:** round-trip Unicode, control characters, and ASCII byte-for-byte under invariant tests; malformed Base64 remains a typed error. **Depends:** Phase 9 credential migration should retain compatibility tests for legacy ciphertext. **Source:** source audit.

7. **[Fix][S][P1] Guard ARM pagination against repeated next links.** `ArmTransport.GetListAsync` trusts every `nextLink` and loops until null without cycle detection or a page budget. Detect repeated absolute URLs and enforce a configurable conservative ceiling with an actionable partial-result error. **Anchor:** `src/AzureDesignStudio.Discovery/Arm/ArmTransport.cs:22-37`. **Accept:** a repeated nextLink fails fast; normal multi-page and empty-list responses remain unchanged. **Depends:** none. **Source:** source audit; Microsoft provider APIs document paged/list operations and ARM next-link behavior [S5].

8. **[Feature][M][P1] Add a dry-run provider/API/location compatibility report.** For each exported resource, query subscription provider metadata and compare registration state, resource type, API version, and region with the generated template; never register a provider automatically. This converts Azure's documented `NoRegisteredProviderFound` and `MissingSubscriptionRegistration` causes into preflight guidance while preserving least privilege. **Anchor:** `AzureApiVersions.cs:10-36`; `TenantInventory.cs:14-21`; `DeployService.cs` prepare/what-if path. **Accept:** fixtures for missing provider, unsupported region, unsupported API version, and valid resource yield distinct results; no `/register/action` request is sent. **Depends:** Phase 9 credential gate; provider metadata cache. **Source:** [S5][S6].

### Workspace reliability, evidence and performance (9–16)

9. **[Feature][M][P1] Maintain a signed-off capability snapshot for each scan.** Persist an as-of version of the scan's data-source probes, provider coverage, query identifiers, and explicitly unavailable sources beside the manifest; current permission preflight is transient. **Anchor:** `ScanEngine.cs:9-35`; `TenantScanSession.cs:33-37`; `WorkspaceScans.cs:83-95`. **Accept:** opening any historical scan reproduces which sources were available and which were skipped, without re-running tenant calls. **Depends:** none. **Source:** Eraser's first-party docs specify on-demand scans and a model based on the last scan [S1][S2]; ADS should preserve the evidence that qualifies its own snapshots.

10. **[Feature][M][P1] Implement retention and compaction for scan snapshots.** Completed scans and their full properties currently accumulate; add per-scope retention tiers and a preview-before-prune operation that preserves pinned scans and all referenced plans/audit evidence. **Anchor:** `WorkspaceScans.cs:59-80,98-125`; `WorkspaceDbContext.cs:31-44`. **Accept:** policy simulation reports exact rows/bytes affected; pruning is transactional, cannot delete pinned/referenced scans, and frees disk space verified by a test DB. **Depends:** Phase 4 migrations/backup/restore. **Source:** source audit; design is a local-first distinction from hosted scan-history competitors [S1][S3].

11. **[Fix][M][P1] Bound latest-scan lookup to one record.** `GetLatestCompletedAsync` includes snapshot collections for every completed scan, materializes them all, and sorts in memory to return just one scan. Add a sortable persisted UTC key (or equivalent provider-safe key) and query the single latest scan before including its rows. **Anchor:** `WorkspaceScans.cs:98-107`. **Accept:** query instrumentation proves one scan's snapshots are materialized regardless of history length; SQLite fixture with many completed scans selects the correct latest. **Depends:** Phase 4 migration authority. **Source:** source audit.

12. **[Infra][M][P1] Record/replay sanitized ARM and ARG response fixtures.** Add an opt-in diagnostic recorder for deterministic reproduction of collector/parser bugs, storing only explicitly redacted response bodies and required status/headers; never persist bearer tokens or request secrets. **Anchor:** `ArmTransport.cs:91-138`; `ResourceGraphClient.cs:79-152`; `DeploymentOperationsParser.cs`. **Accept:** a captured fixture replays offline to identical normalized results, redaction tests find no authorization headers or seeded secrets, and normal requests emit no transcript by default. **Depends:** Phase 8 test harness. **Source:** source audit; Microsoft documents provider responses as heterogeneous/versioned inputs [S5].

13. **[Infra][S][P1] Verify source-generator determinism and generated-source provenance.** Add a test/build diagnostic that records the generator/template inputs and checks repeated generation yields byte-identical output; report the owning Scriban template when generated ARM mappings change. **Anchor:** `src/AzureDesignStudio.SourceGeneration/`; `AzureResources` generated ARM models; `ResourceBaseJsonConverter.cs`. **Accept:** two generator runs over the same inputs produce identical output, and a golden diff traces every changed generated symbol back to a template/input. **Depends:** none. **Source:** source audit; this is not the Phase 8 AutoMapper replacement already planned.

14. **[Feature][M][P2] Add schema-versioned snapshot readers and upgrade tests.** Current workspace bootstrap uses `EnsureCreated` plus hand-written additive DDL; codify a reader contract for older scan manifests and BOM schemas so future fields are additive and old workspaces remain readable. **Anchor:** `WorkspaceDbContext.cs:74-115`; `WorkspaceScans.cs:129-138`; `BillOfMaterials.cs:19`. **Accept:** checked-in synthetic v1 workspace and manifest fixtures load/upgrade to current schema with row counts and hashes preserved. **Depends:** Phase 4 migration baseline. **Source:** source audit.

15. **[Feature][S][P1] Make local evidence privacy inspectable and redactable.** Before BOM/evidence export, classify and redact credential-shaped values and provider fields that are sensitive; present a preview of removed paths, not values, and keep original local snapshot unchanged. **Anchor:** `InventoryNormalizer.FromArgRow` (`InventoryItem.cs:49-64`); `BillOfMaterials.cs:38-48`; `WorkspaceScans.cs:64-75`. **Accept:** seeded secret-like property values are redacted in exports, false-positive overrides are explicit, and source DB bytes are unchanged. **Depends:** privacy classification design; no telemetry enabled by default. **Source:** Bicep's official linter includes explicit rules for secret outputs/parameters and secure parameters [S7].

16. **[Feature][M][P2] Provide a dependency-free offline Bicep lint/diagnostic path.** Reuse the official Bicep CLI/linter when available and expose its configured diagnostics against generated Bicep; report CLI absence distinctly and never claim full server validation offline. **Anchor:** `AdsBicepDecompiler` registration and `CodeDrawerTemplate.razor.cs`; `Core/Common/ArmTemplate.cs`. **Accept:** pinned test fixtures show each surfaced rule, custom config changes rule severity, and unavailable CLI yields “not run” rather than pass. **Depends:** Phase 9 trust gate; package/runtime decision. **Source:** [S7].

### Analysis quality and explainability (17–23)

17. **[Feature][M][P1] Add a bounded Azure Resource Graph query workspace.** Expose read-only KQL against the existing Resource Graph client with a starter-query catalog, subscription scope selector, preview/results schema, explicit result truncation and quota state; hard-limit duration/rows and disallow arbitrary ARM write operations. **Anchor:** `ResourceGraphClient.QueryPageAsync` / `QueryAllAsync`; `AdsToolEngine.InventoryQuery`; `AdsMcpTools`. **Accept:** query fixtures show scope is explicit, paging/truncation is visible, quota reset is surfaced, and no tool path can issue ARM mutations. **Depends:** item 9; Phase 9. **Source:** Microsoft describes ARG's KQL query, governance exploration, user-level throttling headers, and eventual consistency [S10].

18. **[Feature][M][P1] Turn ARM deployment errors into a stable structured diagnostic tree.** Preserve ARM code, message, nested details/inner errors, target resource ID, request/correlation ID, and retryability instead of collapsing errors into display text. **Anchor:** `ResourceGraphException.FromErrorBody`; `ArmTransport.cs:81-89`; `DeployService.cs` error mapping. **Accept:** nested-error fixtures round-trip without losing fields and client UI displays a stable diagnostic code plus raw details behind an expand affordance. **Depends:** Phase 8 stable error-code catalog (not replacing it). **Source:** [S6].

19. **[Feature][M][P1] Introduce a local resource-type extension manifest.** Allow a validated user-provided schema/icon/property projection for unknown resources while keeping unknown resources explicitly typeless and out of deploy/export until a real ARM model exists. **Anchor:** `InventoryItem.cs:8-21`; `UnknownNodeModel.cs`; stencil loader in `AdsContext.cs`. **Accept:** custom extension enriches inventory only, invalid schema is rejected, and no extension can silently enable deployment. **Depends:** no new UI before Phase 9; catalog contract. **Source:** Eraser documents configurable references to scanned models for selective diagrams [S2].

20. **[Feature][M][P2] Add semantic relationship confidence and provenance.** For topology edges, distinguish directly observed ARM references from inferred heuristics, include source property/path and observation time, and let the analyst filter to authoritative edges. **Anchor:** `TopologyDeriver`; `ReachabilityEngine`; `TopologyView.razor`. **Accept:** every rendered edge maps to a source record or is visibly labeled inferred; unknown/missing data never becomes a positive reachability assertion. **Depends:** none. **Source:** Eraser's cloud diagram docs say generated diagrams use the latest scanned model, not live data [S2]; ADS should show provenance at edge level.

21. **[Fix][M][P1] Make inventory content hashes and diffs use one canonical representation.** `InventoryNormalizer.ContentHash` omits `Raw` properties and sorts tags with default comparer; `ScanDiffer` compares the full property tree. Unify both on canonical typed fields/properties and resource ID ordering so a diff cannot report a property change while before/after hashes match. **Anchor:** `InventoryItem.cs:66-75`; `ScanDiffer.cs:45-79,115-124`; `BillOfMaterials.cs:51-60`. **Accept:** arbitrary nested property and tag changes always change the same digest used by BOM/diff; permutation-only JSON key order does not. **Depends:** item 1. **Source:** source audit.

22. **[Feature][M][P2] Explain modeled-vs-unmodeled export coverage in generated artifacts.** Produce an export coverage manifest listing resources successfully emitted, intentionally omitted, and degraded to generic/unknown representation; fail closed for an explicitly requested complete deployment bundle. **Anchor:** `UnknownNodeModel.cs`; `ResourceBaseJsonConverter.cs`; `ArmTemplate.cs`; `CodeDrawerTemplate.razor.cs`. **Accept:** each input node appears exactly once in the coverage manifest; “complete” export is impossible when any resource is omitted or degraded. **Depends:** item 13. **Source:** Microsoft says exported/typed templates can fail when provider/API/location combinations are unsupported [S6].

23. **[Fix][M][P1] Confirm deletion candidates against ARG's eventual consistency.** `ScanDiffer` classifies every ID missing from the second snapshot as Removed, while Microsoft documents Resource Graph as eventually consistent. Add a confirmation state (for example, a subsequent scan or targeted read-only ARM GET) before treating a single-snapshot absence as a confirmed deletion; keep “not observed” separate from “deleted.” **Anchor:** `ScanDiffer.cs:45-60`; `ResourceGraphClient.cs:48-75`. **Accept:** a temporarily missing row yields UnconfirmedMissing, reappearance clears it, and confirmed absence requires a separate evidence path. **Depends:** item 9; the provider confirmation call must remain read-only. **Source:** [S10].

### Post-trust-gate UI modernization (24–30)

All seven proposals are explicitly deferred until the Phase 9 Trust Gate is complete; they add UI surfaces rather than completing current Phase 7 shell commitments.

24. **[UX][M][P1] Add a portfolio comparison workspace.** Compare two chosen subscriptions/scans side-by-side with matched resource rows, unmatched rows, per-field deltas, and separate scope labels; do not merge scopes or imply that equal names mean equal resources. **Anchor:** `TenantInventory.cs`; `ScanDiffer.cs`; `CompareDrawerTemplate.razor`. **Accept:** ARM IDs are the identity key, scope mismatch is explicit, and a fixture with colliding resource names stays unambiguous. **Depends:** Phase 9; stable two-scan contract. **Source:** Hava documents arbitrary revision comparison as a useful analysis pattern [S3].

25. **[UX][M][P1] Build an evidence-coverage heatmap for scan results.** Show scope × data-source/query coverage as succeeded, partial, denied, or not applicable, linking each cell to the scan manifest; put gaps ahead of aggregate “healthy” scores. **Anchor:** `ScanCheckpoint.FailedQueries` in `ScanEngine.cs:16-23`; `PermissionPreflight`; `TenantScanDrawerTemplate.razor`. **Accept:** partial/denied results are visible without opening a log, and the heatmap never converts missing observations into compliant status. **Depends:** item 9; Phase 9. **Source:** Eraser documents that its visual model is based on the latest scan and requires rescan [S2].

26. **[UX][M][P2] Add a provider compatibility review board.** Before export/apply, group affected resources by missing provider registration, unsupported API version, unsupported region, or unknown metadata; offer copyable manual remediation but no hidden registration action. **Anchor:** `AzureApiVersions.Map`; `CodeDrawerTemplate.razor`; item 8 engine. **Accept:** every blocking finding links to resource and evidence, and no mutation control exists in the review surface. **Depends:** item 8; Phase 9. **Source:** item 8 proposal plus the official provider metadata and registration error documentation [S5][S6].

27. **[UX][M][P1] Render structural property-shape changes explicitly.** Surface empty-object/array/null shape changes as a distinct “structure changed” row; the current `ScanDiffer.Flatten` emits only leaves, so `{}` and `[]` can vanish from the property diff. **Anchor:** `src/AzureDesignStudio.Discovery/Drift/ScanDiffer.cs:115-143`; `CompareDrawerTemplate.razor:106-128`. **Accept:** `{}`→`[]`, `{}`→`null`, empty array→one-item array, and object key reordering have clear expected rendering and no false-positive churn. **Depends:** item 21; Phase 9. **Source:** source audit.

28. **[UX][M][P2] Add a type-safe bulk property inspector for selected nodes.** When multiple compatible resource nodes are selected, show shared properties, mixed values, and the set of nodes that would change; apply only schema-valid local design edits and never imply that Azure has been changed. **Anchor:** `DesignInspector.razor`; `AdsContext` selection/diagram state; per-resource `*Form.razor` components. **Accept:** mixed values display distinctly, unsupported cross-type fields are unavailable, undo restores all changes as one action, and selection changes cannot leak edits to a prior design. **Depends:** Phase 9; component/undo contracts. **Source:** repository source at baseline `fa62bb9` [S8], with the existing Round 2 component-test gate referenced in `.planning/ROADMAP.md` Phase 8.

29. **[UX][S][P1] Surface uncertainty with a consistent observed/inferred/unknown visual language.** Use shape plus text labels (not color alone) for verified facts, derived relations, stale metadata, and missing data across topology and preflight views. **Anchor:** `TopologyView.razor`; `ExposureAnalyzer.cs`; `DeprecationCatalog.cs:36-49`. **Accept:** all four states remain distinguishable in grayscale, high contrast, and keyboard-only use; explanatory legend is always reachable. **Depends:** item 20; Phase 9. **Source:** repository source at baseline `fa62bb9` [S8] plus W3C accessibility guidance cited in the UI modernization plan.

30. **[UX][M][P2] Deliver the KQL workbench as a first-class analysis surface.** Pair an editable read-only query pane with table/schema hints, explicit subscription scope, quota/truncation status, and a results grid whose columns and export match the query result. Keep it separate from the canvas and existing command palette. **Anchor:** `ResourceGraphClient.cs`; `TenantScanDrawerTemplate.razor`; `InventoryFacets.cs`. **Accept:** query scope and data freshness are always visible, keyboard users can edit/run/navigate results, truncated results cannot be mistaken for a complete inventory, and the browser host degrades cleanly. **Depends:** item 17; Phase 9. **Source:** Microsoft Azure Resource Graph documentation cited at [S10], plus repository source at baseline `fa62bb9` [S8].

## Recommended sequence

First 10, in dependency order: **1 → 21 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9**. Fix content integrity and terminal scan correctness before exposing more analysis; then make snapshot writes/resume safe, close tree/pagination defects, and add provider compatibility evidence. Items 10–16 improve durability after the migrations/backup gate. Items 17–23 expand bounded read-only analysis. Items 24–30 are all deferred until after Phase 9 and only follow once their underlying data contracts are trustworthy. No proposal authorizes Azure mutations or changes the approved roadmap.

## What not to build

- Do not auto-register resource providers as a convenience: Microsoft explicitly recommends registering only providers ready for use; report the missing provider and the required role instead [S5].
- Do not claim that provider metadata proves capacity or that a successful what-if guarantees a successful deployment; report unavailable/unknown facts as unknown.
- Do not embed or run an LLM against tenant inventory by default; keep evidence deterministic, local, and attributable.
- Do not replace Bicep/ARM with Terraform or a new home-grown deployment engine; preserve the Azure-native product thesis and existing execution gates.
- Do not start UI work before the Phase 9 trust gate; proposals 24–30 are conditional, not a roadmap rescope.
- Do not claim competitor feature absence beyond the official docs reviewed; describe documented scope and its limitations only.
